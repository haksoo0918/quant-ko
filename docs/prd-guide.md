# PRD 작성 및 에이전트 협업 가이드 (PRD Guide)

본 문서는 바이브코딩(Vibe Coding) 환경에서 제품 요구사항 정의서(PRD)를 효과적으로 작성하고, AI 에이전트와의 협업에서 단일 진실 공급원(Single Source of Truth)으로 유지하는 방법을 안내합니다.

---

## 1. 바이브코딩에서 PRD가 왜 가장 중요한가?

바이브코딩의 성패는 **"에이전트가 개발자의 의도를 얼마나 정확하게 맥락(Context)으로 인지하고 있는가"** 에 달려 있습니다.

- **컨텍스트 표류(Drift) 방지**: 대화가 길어지면 LLM은 이전 턴의 세부 결정을 잊어버리거나 왜곡할 수 있습니다. `PRD.md`는 항상 최신 결정 사항을 고정해 두는 앵커(Anchor) 역할을 합니다.
- **불필요한 코드 재작업 차단**: 코드를 짜기 전에 사양과 데이터 모델을 먼저 합의하면, 코드 작성 후 발생하는 구조적 실패와 롤백을 90% 이상 예방할 수 있습니다.
- **승인 관문(Gatekeeper)**: PRD를 수정하고 사용자에게 승인을 받는 과정을 통해 AI의 독단적인 코드 수정을 물리적으로 통제할 수 있습니다.

## 2. PRD 핵심 섹션별 작성 팁

### 2.1 개요 및 목표 (Overview & Goals)
- **배경**: 왜 이 프로젝트/기능을 만드는가?
- **핵심 목표**: 달성해야 할 구체적인 결과물 3~4가지.
- **비목표 (Non-Goals)**: 의도적으로 이번 범위에서 제외할 것 (에이전트가 오버엔지니어링하는 것을 방지).

### 2.2 사용자 페르소나 및 핵심 시나리오
- 주 사용자층과 사용자가 겪는 핵심 고통(Pain Points).
- 사용자가 이 기능을 통해 완수하는 대표적인 성공 시나리오(Happy Path).

### 2.3 기능 요구사항 및 우선순위 (MoSCoW / P-Level)
- **P0 (Must-Have)**: 이것 없이는 제품이 작동하지 않는 핵심 필수 기능.
- **P1 (Should-Have)**: 주요 기능이지만 1차 릴리즈 직후 구현 가능한 기능.
- **P2 (Nice-to-Have)**: 여유가 있을 때 추가할 편의 기능이나 고도화 항목.

### 2.4 데이터 모델 및 인터페이스 (Data & Schema)
- 엔터티 관계, 필수 필드 타입, 식별자(PK/FK).
- 주요 API 엔드포인트 명세 (경로, 메서드, 요청/응답 예시).

### 2.5 화면 흐름 및 UI/UX 명세
- 주요 화면 목록 및 화면 간 전환 플로우.
- 필수 UI 컴포넌트 및 비어 있는 상태(Empty), 로딩 상태(Loading), 에러 상태(Error) 정의.

### 2.6 에이전트 승인 체크리스트
- 코드 구현 전 에이전트가 자가 점검할 필수 체크리스트.
- *(참고: 버전별 릴리즈 및 세부 변경 이력은 PRD에 중복 작성하지 않고 `CHANGELOG.md`에서 전담 관리합니다.)*

## 3. 에이전트에게 PRD 작성/수정을 요청하는 프롬프트 예시

### 3.1 신규 아이디어에서 PRD 초안 생성 요청
```text
새로운 프로젝트 아이디어가 있어. [아이디어 간단 설명].
우리 프로젝트의 rules/protocol-ko.md에 따라, 바로 코드를 작성하지 말고
먼저 인터뷰를 통해 세부 요구사항을 정의하자. /grill-me 커맨드를 사용해줘.
```

### 3.2 신규 기능 추가 시 PRD 선반영 요청
```text
[기능 이름] 기능을 추가하려고 해.
먼저 ./PRD.md에 기능 요구사항(우선순위, 데이터 모델 영향도, 승인 체크리스트)을 업데이트하고,
내가 검토할 수 있도록 변경 요약과 함께 승인을 요청해줘. 승인 전에는 코드를 만지지 마.
```

## 4. PRD 생명주기 관리 원칙

1. **단 하나의 활성 PRD**: 저장소 루트의 `PRD.md`가 유일한 기준점입니다. 구버전 PRD는 Git 히스토리로 관리합니다.
2. **지속적 갱신**: 개발 도중 기획이나 기술적 제약으로 설계가 바뀌면, 즉시 PRD를 수정하여 최신 상태를 유지합니다.
3. **완료 표시**: 기능이 구현되고 테스트를 통과하면 PRD의 체크리스트(`- [x]`)를 완료 처리합니다.

# MCP 서버 & Antigravity 스킬 활용 가이드 (MCP & Skills Guide)

본 문서는 Google Antigravity 및 Gemini 에이전트 환경에서 작업 효율성을 극대화하기 위한 **추천 MCP(Model Context Protocol) 서버** 와 **스킬(Skills) 및 슬래시 커맨드** 활용법을 정리한 가이드입니다.

---

## 1. 추천 MCP 서버 (Recommended MCP Servers)

MCP는 AI 에이전트가 외부 도구, 데이터베이스, 공식 문서와 안전하게 소통할 수 있도록 연결해 주는 표준 프로토콜입니다.

### 1.1 Context7 (공식 기술 문서 실시간 검색)
- **용도**: LLM의 지식 컷오프 이후 출시된 최신 라이브러리, 프레임워크 API 문서를 실시간 검색.
- **주요 도구**: `resolve-library-id`, `query-docs`
- **효과**: 프레임워크 버전 업데이트로 변경된 신규 문법(예: Next.js App Router, Vite v6 등)의 환각(Hallucination) 방지.
- 💡 **실제 활용 예시**:
  - *개발자*: "Zod v3 최신 문법으로 이메일 유효성 검사 스키마 짜줘."
  - *에이전트*: 에이전트가 과거 기억에 의존해 잘못된 메서드를 쓰지 않고, 내부적으로 `Context7` 도구를 호출하여 Zod의 최신 공식 문서를 직접 확인한 후 100% 검증된 코드를 작성합니다.

### 1.2 GitHub MCP Server
- **용도**: GitHub 저장소의 이슈, 풀 리퀘스트(PR), 커밋 이력, 코드 검색 연동.
- **주요 도구**: `create_issue`, `create_pull_request`, `list_commits`, `search_code`
- **효과**: 이슈 기반 작업 추적 및 에이전트를 통한 자동화된 PR 생성.
- 💡 **실제 활용 예시**:
  - *개발자*: "이 저장소의 #12번 이슈 내용 확인하고 그에 맞춰 코드 수정해줘."
  - *에이전트*: 에이전트가 GitHub API로 12번 이슈의 제목, 본문, 댓글을 조회한 뒤 요구사항을 파악하여 구현에 착수합니다.

### 1.3 Chrome DevTools MCP Server
- **용도**: 브라우저 콘솔 로그 검사, 접근성(a11y) 진단, 웹 성능(Core Web Vitals) 측정.
- **주요 도구**: `list_pages`, `new_page`, `navigate_page`
- **효과**: 프론트엔드 UI 화면의 렌더링 상태를 직접 확인하고 시각적 버그를 조기 포착.
- 💡 **실제 활용 예시**:
  - *개발자*: "로컬 3000번 포트 열어서 모바일 뷰포트에서 메뉴 버튼 잘 눌리는지 확인해봐."
  - *에이전트*: 헤드리스 크롬으로 페이지에 접속해 가상 클릭을 해보고, 콘솔 에러가 발생했는지 스크린샷과 로그로 직접 검증합니다.

## 2. Antigravity 핵심 슬래시 커맨드 (Slash Commands)

Antigravity 대화창에서 슬래시(`/`) 커맨드를 입력하여 고도화된 워크플로우를 트리거할 수 있습니다:

| 슬래시 커맨드 | 용도 및 권장 시점 | 실제 입력 예시 |
| :--- | :--- | :--- |
| **`/grill-me`** | **[강력 추천]** 프로젝트 초기 단계나 신규 기능 기획 시, 에이전트가 역으로 집요하게 질문을 던져 설계를 구체화하는 인터뷰 모드. | `/grill-me 노션 같은 미니 메모 웹앱을 만들고 싶어.` |
| **`/plan`** | 복잡하고 영향 범위가 큰 기능 구현 전, 단계별 체크리스트와 변경 계획을 체계적으로 수립할 때. | `/plan 구글 OAuth2 로그인과 세션 인증 미들웨어를 붙여줘.` |
| **`/goal`** | 에이전트가 스스로 테스트를 돌리고 실패하면 수정하며 완성될 때까지 멈추지 않고 완주하도록 할 때. | `/goal 결제 모듈 단위 테스트가 100% 통과할 때까지 자율 디버깅해줘.` |
| **`/learn`** | 사용자가 에이전트의 잘못을 교정했거나 특정한 프로젝트 규칙을 영구 기억시켜 다음 세션에도 유지하고자 할 때. | `/learn 우리 프로젝트는 순수 모던 CSS 변수와 @container만 쓴다.` |
| **`/boost`** | 다각도의 심층 추론, 복잡한 알고리즘 최적화, 아키텍처 재설계가 필요할 때. | `/boost 대용량 로그 스트리밍 파이프라인의 메모리 누수 원인을 분석해줘.` |

### 2.1 슬래시 커맨드 실제 대화 시나리오 예시

#### 예시 1: `/grill-me` (대화형 요구사항 인터뷰)
```text
개발자: /grill-me 북마크 관리 서비스를 만들고 싶어.

에이전트:
좋습니다! 탄탄한 PRD 작성을 위해 몇 가지 핵심 질문을 드릴게요:
1. 저장소: 브라우저 로컬스토리지에만 저장하나요, 아니면 서버 DB와 동기화하나요?
2. 메타데이터: 링크를 입력했을 때 웹사이트 제목과 썸네일(OG Tag)을 자동으로 긁어와야 하나요?
3. 태그/분류: 폴더형 계층 구조인가요, 해시태그 기반 평면 구조인가요?
답변 주시면 바로 PRD.md에 반영하겠습니다!
```

#### 예시 2: `/plan` (구조화된 단계별 실행 계획)
```text
개발자: /plan 결제 취소 및 환불 API 연동해줘.

에이전트:
환불 기능 구현 계획을 아래 4단계로 수립했습니다:
- [ ] 1단계: 토스페이먼츠 환불 API 스펙 검토 및 에러 코드 정의
- [ ] 2단계: 결제 취소 요청 DTO 유효성 검사 및 테스트 코드 작성
- [ ] 3단계: 주문 상태 롤백 트랜잭션 및 DB 업데이트 로직 구현
- [ ] 4단계: 모의 테스트 결제건으로 환불 E2E 검증
이 계획대로 진행할까요?
```

## 3. 서브에이전트 (Subagents) 활용 전략

### 3.1 서브에이전트란 무엇인가요?
- **직관적 비유**: 메인 에이전트(팀장)가 복잡한 일이나 방대한 조사를 처리할 때 파견하는 **"독립된 임시 비서"** 입니다.
- **왜 필요한가? (컨텍스트 오염 방지)**:
  - 혼자서 20~30개 파일을 다 열어보고 웹 검색 결과를 수천 줄 읽으면, 메인 대화창의 **기억 용량(컨텍스트 윈도우)이 금방 꽉 차서 이전 대화를 잊어버리고 멍청해집니다.**
  - 서브에이전트는 **자신만의 격리된 방(별도 세션)** 에서 자료 조사를 싹 마친 뒤, **핵심 요약 결론만 메인 대화창에 보고하고 사라집니다.** 덕분에 메인 대화창은 항상 가볍고 총명한 상태를 유지합니다.

### 3.2 대표적인 서브에이전트 종류
1. **`research` (조사 전담 비서)**:
   - 읽기 전용 도구(코드 검색, 파일 읽기, 웹 검색)만 갖추고 안전하게 대규모 조사 수행.
   - 프로젝트 전체의 아키텍처 흐름 분석, 외부 기술 문서 심층 탐색에 사용.
2. **`self` (복제 분신 비서)**:
   - 메인 에이전트와 동일한 권한을 갖고, 메인 브랜치를 더럽히지 않는 격리된 임시 작업 공간(Branch/Share)에서 위험한 코드 실험이나 가설 검증 수행.

### 3.3 개발자가 서브에이전트를 실제로 써먹는 3대 실전 활용법

#### 1. "딴짓 시키기" (병렬 작업)
- **상황**: 메인 대화창에서 UI 코딩을 계속 진행하면서, 외부 라이브러리 조사나 긴 문서 분석도 동시에 필요할 때.
- **개발자가 할 말**:
  > *"나랑은 화면 계속 만들고, **서브에이전트 하나 띄워서** 포트원 결제 연동 문서랑 예제 코드 조사해 놔."*
- **효과**: 코딩 흐름을 끊지 않고, 백그라운드에서 조사가 끝나면 요약 보고만 쏙 받습니다.

#### 2. "대화창 멍청해지는 것 방지" (컨텍스트 보호)
- **상황**: 수십 개 파일이 얽힌 복잡한 로직이나 레거시 코드를 파악해야 할 때.
- **그냥 시키면**: 에이전트가 30개 파일을 대화창에 줄줄이 읽어 들여서 **이전 대화 기억을 다 까먹고 멍청해집니다.**
- **개발자가 할 말**:
  > *"대화창 더러워지지 않게 **서브에이전트로** 우리 프로젝트 전체 결제 흐름 추적해서 3줄로만 요약해줘."*
- **효과**: 메인 대화창은 단 3줄의 깨끗한 상태를 유지하므로, AI의 지능과 기억력이 끝까지 유지됩니다.

#### 3. "위험한 실험 시키기" (내 코드 안 건드리고 시도)
- **상황**: 코드를 대대적으로 뜯어고치거나 아키텍처를 바꿨을 때 에러가 얼마나 터질지 미리 보고 싶을 때.
- **개발자가 할 말**:
  > *"내 현재 작업 건드리지 말고, **서브에이전트 격리 브랜치로 띄워서** 라이브러리 v4로 업그레이드하면 빌드 깨지는지 테스트해봐."*
- **효과**: 내 소스 코드는 안전하게 그대로 둔 채, 복제된 임시 공간에서 실험 결과만 보고받습니다.

## 4. 추천 스킬(Skills) 및 간편 설치 가이드

스킬(`SKILL.md`)은 에이전트에게 특정 분야(디자인, TDD, 코드 리뷰, SEO 등)의 전문 지식과 작업 가이드라인을 주입하는 확장 기능입니다.

전체 스킬 목록과 인기 스킬은 🌐 **[Skills.sh 공식 사이트](https://skills.sh/)** 및 디자인 엔지니어링 스킬을 모아둔 🌐 **[UI Skills](https://www.ui-skills.com/)** 에서 실시간으로 검색하고 탐색할 수 있습니다.

> [!NOTE]
> 본 스타터 템플릿에는 **`ui-ux-pro-max`**, **`seo`**, **`tdd`**, **`code-review`** 4개 핵심 스킬이 프로젝트 루트(`.agents/skills/`)에 **기본 설치 및 탑재** 되어 있습니다. 별도의 추가 설치 없이 바로 서브에이전트 파이프라인 및 슬래시 커맨드에서 작동합니다.

### 4.1 추천 스킬 목록 및 한 줄 소개

| 스킬 명칭 | 탑재 상태 | 저장소 / 출처 | 주요 용도 및 소개 |
| :--- | :--- | :--- | :--- |
| **`ui-ux-pro-max`** | ✅ **기본 탑재** (`.agents/skills/`) | `nextlevelbuilder/ui-ux-pro-max-skill` | 사용성, 시각적 계층 구조, 인터랙션 디테일을 전문가 수준으로 끌어올리는 종합 UI/UX 디자인 시스템 |
| **`seo`** | ✅ **기본 탑재** (`.agents/skills/`) | `addyosmani/web-quality-skills` | Google 웹 품질 엔지니어 Addy Osmani의 검색 엔진 최적화(SEO) 및 웹 성능(CWV) 베스트 프랙티스 |
| **`tdd`** | ✅ **기본 탑재** (`.agents/skills/`) | `mattpocock/skills` | TypeScript 전문가 Matt Pocock의 테스트 주도 개발(TDD) 워크플로우 및 실패-성공-리팩토링 사이클 가이드 |
| **`code-review`** | ✅ **기본 탑재** (`.agents/skills/`) | `mattpocock/skills` | 코드 가독성, 타입 안전성, 엣지 케이스 처리, 유지보수성을 엄격하게 점검하는 전문 AI 코드 리뷰 |
| **`frontend-design`** | ➕ 선택 추가 | `anthropics/skills` | 모던하고 세련된 프론트엔드 UI 컴포넌트 구현 및 디자인 감각을 극대화하는 스타일링 가이드 |
| **`seo-audit`** | ➕ 선택 추가 | `coreyhaines31/marketingskills` | 마케팅 관점에서 웹사이트의 기술적 SEO 취약점, 메타태그, 소셜 공유 미리보기(OG)를 정밀 진단 |

### 4.2 추가 스킬 터미널 설치 명령어 (npx skills add)

기본 탑재된 4종 외에 추가적인 스킬이 필요한 경우, 터미널에서 아래 명령어를 실행하여 추가할 수 있습니다:

```bash
# 선택: 프론트엔드 UI 디자인 감각 보강
npx skills add https://github.com/anthropics/skills --skill frontend-design

# 선택: 마케팅 및 기술적 SEO 정밀 감사
npx skills add https://github.com/coreyhaines31/marketingskills --skill seo-audit
```

### 4.3 스킬 호출 방법 (슬래시 커맨드)

설치된 스킬은 대화창에서 **`/<스킬명>`** 슬래시 명령어를 입력하여 직접 호출할 수 있습니다:

- `/<스킬명> [요청사항]`: 설치된 스킬의 가이드라인을 강제 적용하여 작업을 지시합니다.
  - *예시*: `/frontend-design 로그인 모달 컴포넌트 작성해줘`
  - *예시*: `/tdd 장바구니 할인 쿠폰 계산 로직 구현해줘`
  - *예시*: `/code-review 방금 작성한 결제 모듈 코드 검토해줘`

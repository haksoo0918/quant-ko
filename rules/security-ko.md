# 보안 및 민감정보 보호 규칙 (Security Guidelines)

본 문서는 민감한 데이터를 보호하고 프로젝트 내 파괴적인 작업을 사전에 방지하기 위한 필수 보안 프로토콜을 규정합니다.

## 1. 비밀 정보 및 자격 증명 보호

1. **하드코딩 절대 금지**: API 키, 액세스 토큰, 비밀번호, 비밀키(Private Key), 데이터베이스 접속 문자열, 클라우드 자격 증명을 소스 코드에 직접 기입하지 마십시오.
2. **환경변수 분리 관리**:
   - 모든 런타임 보안 정보와 설정은 `.env` 또는 로컬 설정 파일로 분리합니다.
   - 실제 값 대신 더미 플레이스홀더를 담은 `.env.example` 파일을 작성하여 버전 관리에 포함시킵니다.
3. **커밋 전 사전 검증**:
   - `.env`, `.env.local`, 인증서 파일 등이 `.gitignore`에 등록되어 있는지 확인합니다.
   - 터미널 로그, 대화 기록, 커밋 메시지에 비밀키 값을 그대로 출력(`echo`, `print`)하지 않습니다.

---

## 2. 파괴적 작업 안전 프로토콜

1. **위험 명령어 실행 금지**: AI 에이전트는 사용자의 명시적이고 사전 승인 없이는 복구 불가능한 파괴적 명령어를 실행할 수 없습니다:
   - 파일 및 디렉터리 강제 삭제: `rm -rf`, `Remove-Item -Recurse -Force`, `shred`
   - Git 강제 작업 및 히스토리 조작: `git reset --hard`, `git clean -fd`, `git push --force`, `git push <remote> +<ref>` (강제 덮어쓰기 구문 일체)
   - 데이터베이스 삭제: `DROP DATABASE`, `TRUNCATE TABLE`, 비가역적 마이그레이션 롤백
   - 시스템 변경: 디스크 포맷, 방화벽 임의 변경, 전역 시스템 패키지 삭제
2. **무단 복구 및 롤백 절대 금지**:
   - 오류나 예외 상황 발생 시 복구, 롤백, 데이터 강제 덮어쓰기 등의 작업을 독단적으로 시도하지 않습니다.
   - 즉시 모든 명령어 실행을 멈추고 현재 상태를 객관적으로 보고한 뒤 사용자의 지시를 기다립니다.
3. **안전한 대안 사용**:
   - 필요한 경우 삭제 대신 임시 백업 디렉터리로 이동하거나 비파괴적 검사를 우선 수행합니다.
   - 삭제 명령어 실행 전 작업 디렉터리 경로(Cwd)를 반드시 재확인합니다.

---

## 3. 의존성 및 공급망 보안

1. **검증된 패키지 설치**: 공식 패키지 레지스트리(npm, PyPI, crates.io 등)의 안정적이고 신뢰할 수 있는 공식 라이브러리만 사용합니다.
2. **락 파일(Lockfile) 유지**: 재현 가능하고 변조되지 않은 빌드를 보장하기 위해 락 파일(`package-lock.json`, `poetry.lock`, `pnpm-lock.yaml` 등)을 항상 커밋합니다.
3. **취약점 점검**: 새로운 의존성을 도입할 때 보안 취약점 점검 도구(`npm audit`, `pip-audit` 등)를 실행하여 안전성을 점검합니다.

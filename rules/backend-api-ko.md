# 백엔드 및 API 아키텍처 규칙 (Backend & API Standards)

본 문서는 서버 개발 프랙티스, RESTful/GraphQL API 설계 원칙 및 데이터베이스 처리 가이드를 정의합니다.

## 1. API 설계 및 리소스 모델링

1. **RESTful 리소스 명명 규칙**:
   - 리소스 엔드포인트에는 복수형 명사를 사용합니다: `/api/v1/users`, `/api/v1/projects/:id/tasks`.
   - 올바른 HTTP 동사를 사용합니다: `GET` (조회), `POST` (생성), `PUT`/`PATCH` (수정), `DELETE` (삭제).
2. **일관된 응답 구조 (Envelope)**:
   - 성공과 실패 응답 모두 일관성 있는 JSON 형식을 반환합니다:
   ```json
   {
     "success": true,
     "data": { ... },
     "error": null,
     "meta": { "page": 1, "total": 42 }
   }
   ```
3. **HTTP 상태 코드 준수**:
   - `200 OK` / `201 Created` / `204 No Content`
   - `400 Bad Request` (유효성 검사 실패 등)
   - `401 Unauthorized` / `403 Forbidden`
   - `404 Not Found`
   - `422 Unprocessable Entity`
   - `500 Internal Server Error`

---

## 2. 입력 검증 및 방어적 프로그래밍

1. **엄격한 스키마 유효성 검사**:
   - 비즈니스 로직 수행 전 스키마 라이브러리(Zod, Pydantic, class-validator 등)를 통해 들어오는 모든 페이로드를 검증합니다.
   - 예상치 못한 파라미터는 엄격하게 차단합니다.
2. **인증 및 인가 검증**:
   - 컨트롤러/라우터 계층에서 세션 또는 토큰 유효성을 선행 확인합니다.
   - 요청자의 세션 정보와 리소스 소유권을 대조하여 인가 우회(IDOR) 취약점을 방지합니다.

---

## 3. 에러 핸들링 및 구조화된 로깅

1. **무음 실패(Silent Failures) 방지**: 모든 예외는 명시적으로 포착하고 처리합니다. 내부 스택 트레이스나 시스템 세부 정보가 사용자 응답에 노출되지 않도록 사용자 친화적인 메시지로 변환합니다.
2. **구조화된 로그 출력**:
   - 타임스탬프, 로그 레벨, 요청 식별자(Request ID), 엔드포인트 정보가 포함된 구조화된 JSON 로그를 출력합니다.
   - 비밀번호, 토큰, 개인정보(PII)는 로그에 절대 남기지 않습니다.

---

## 4. 데이터베이스 작업 및 무결성

1. **다중 트랜잭션 보장**: 여러 엔터티를 수정하는 작업은 반드시 원자적 트랜잭션(`BEGIN ... COMMIT`)으로 처리합니다.
2. **코드 기반 마이그레이션**:
   - 모든 스키마 변경은 마이그레이션 파일로 버전 관리합니다.
   - 컬럼 추가나 타입 변경 시 하위 호환성을 고려하여 롤백 가능성을 확보합니다.

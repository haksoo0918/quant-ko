# 언어 및 마크다운 규칙 (Language & Markdown Standards)

본 문서는 워크스페이스 내 모든 AI 에이전트와 기여자가 준수해야 할 커뮤니케이션, 서식 및 문서화 표준을 정의합니다.

## 1. 자연어 및 언어 사용 원칙

1. **응답 및 소통은 전면 한국어**: 모든 에이전트 답변, 기술적 설명, 진행 상황 보고, 문서 작성은 한국어를 원칙으로 합니다.
2. **코드 주석 및 독스트링 100% 한국어**: 소스 코드 내부의 인라인 주석, 함수/클래스 설명문(Docstrings), 아키텍처 메모는 모두 한국어로 작성합니다.
3. **상수 및 함수 한글 주석 의무화**: 소스 코드에 선언되는 모든 주요 상수(Constants)와 함수/메서드(Functions)에는 용도, 매개변수, 반환값 및 비즈니스 맥락을 설명하는 명확한 한글 주석/독스트링을 필수 작성합니다.
4. **커밋 메시지 한글화**: 커밋 메시지의 타입, 스코프, 요약문, 본문 모두 한글로 작성합니다 (`rules/git-workflow-ko.md` 참조).
5. **식별자 영문 표기**: 컴파일러 및 프로그래밍 언어 표준을 준수하기 위해 변수명, 함수명, 타입/인터페이스명, 파일명, Git 브랜치명은 영문 표준 컨벤션(camelCase, PascalCase, kebab-case 등)을 유지합니다.
6. **에이전트 규칙 문서의 간결성 및 고밀도화 (Concise & High-Signal Rules)**:
   - `GEMINI.md` 및 `rules/*` 등 에이전트 행동 지침을 작성하거나 수정할 때는 배경 설명, 미사여구, 감정적 수식을 완전히 배제합니다.
   - LLM의 주의 집중력(Attention) 보존을 위해 **명확한 명령문(Do & Don't)과 핵심 조건 위주로 간결·명료하게 작성** 합니다.
   - 각 조항은 불필요한 예시 나열을 지양하고 본질적인 제약 사항만 1\~2줄 이내로 압축합니다.
7. **간결성과 근거 기반 설명**: 대화창 답변 시 불필요한 미사여구를 배제하고, 코드 맥락과 공식 문서에 기반한 명확한 기술적 근거를 제시합니다.

## 2. 마크다운 및 서식 표준

1. **GitHub Flavored Markdown (GFM)**: 표준 GFM 표, 할 일 체크리스트 (`- [ ]`), 인용구, 코드 블록을 사용합니다.
2. **알림 콜아웃(Alert Callouts)**: 의미에 맞는 적절한 GitHub 알림 구문을 활용합니다:
   - `> [!NOTE]`: 배경 맥락 및 부가 설명
   - `> [!TIP]`: 성능 팁 및 모범 사례
   - `> [!IMPORTANT]`: 필수 준수 사항 및 제약
   - `> [!WARNING]`: 하위 호환성 단절 및 주의 사항
   - `> [!CAUTION]`: 데이터 손실이나 파괴적 위험 경고
3. **코드 블록 식별자**: 코드 블록 선언 시 항상 언어 식별자(예: `ts`, `bash`, `json`, `mermaid`)를 명시합니다.
4. **강조 구문 뒤 공백 강제**: 한글 마크다운 문서 작성 시 강조 문구(`**...**` 또는 `*...*`) 뒤에 한글 조사나 텍스트가 공백 없이 이어질 경우, 마크다운 파서의 볼드/이탤릭 렌더링 깨짐을 방지하기 위해 반드시 공백을 강제로 삽입합니다 (예: `** 강조** 문구` ❌ ➔ `** 강조** 문구` ⭕).
   - **강조 내부 문구 무관**: 강조 기호 내부의 문구 형태(코드 백틱, 특수문자, 괄호, 와일드카드 등)와 무관하게, **닫는 강조 마크 바로 뒤에 한글(조사/어미/명사)이 올 경우 무조건 공백을 삽입** 합니다 (예: `** 번역본(`*-ko.md`)** 을` ❌ ➔ `** 번역본(`*-ko.md`)** 을` ⭕).
   - **기계적 검증 기준**: `(?<=\S)\*\*(?=[가-힣])` 패턴으로 검사하여 닫는 볼드 태그 직후의 한글 접착을 100% 차단합니다.
5. **물결표(`\~`) 취소선 오인 방지 의무화**: 대화창 답변(In-Chat responses), `ask_question` 모달 도구 파라미터, 아티팩트, 코드 주석 및 마크다운 문서 일체에서 기간이나 범위를 표현할 때 날것의 물결표(`~`) 사용을 금지합니다. 하이픈(`-`, 예: `2023 - 2024년`, `11 - 4월`)을 우선 사용하거나, 물결표 사용 시 반드시 백슬래시 이스케이프(`\~`, 예: `2023\~2024년`, `11\~4월`)를 적용하여 텍스트가 취소선(`~~취소선~~`)으로 오인 렌더링되는 결함을 원천 차단합니다.

## 3. 파일 링크, 저장 위치 및 인코딩 원칙

1. **Strict UTF-8 (No-BOM) 인코딩 강제**: 모든 파일(소스 코드, 마크다운 문서, 설정 파일, 스크립트)은 반드시 BOM 없는 UTF-8로 생성 및 수정합니다. 셸 리다이렉션(`>`, `>>`)이나 기본 인코딩에 의존한 파일 쓰기로 인한 CP949/ANSI 한글 깨짐을 절대 금지합니다.
2. **실물 프로젝트 디렉터리 저장**: 모든 프로젝트 문서와 산출물은 임시/내부 캐시 경로가 아닌 워크스페이스 표준 경로(`docs/` 등)에 실물 파일로 생성합니다.
3. **클릭 가능한 링크 및 본문 동시 제공**: 파일 링크는 에디터 뷰어가 즉시 인식 가능한 `file:///` 스킴을 사용하며, 사용자가 즉시 읽을 수 있도록 핵심 본문을 채팅창에 함께 출력합니다.
4. **가독성 높은 링크 텍스트**: 전체 긴 경로 대신 파일의 기본 이름(예: `protocol.md`, `App.tsx`)을 링크 텍스트로 사용합니다.
5. **슬래시 표준화**: 윈도우 환경이더라도 경로 구분자는 항상 슬래시(`/`)를 사용합니다.

## 4. 수식 및 LaTeX 서식

1. **KaTeX 표준**: 수학 기호 및 공식은 표준 KaTeX 문법을 따릅니다:
   - 인라인 수식: `$x + y = z$` 또는 `\(x + y = z\)`
   - 블록 수식: `$$E = mc^2$$` 또는 `\[E = mc^2\]`
2. **달러 기호 이스케이프**: 통화 표시나 셸 변수(예: `$HOME`, `$100`)는 백틱(`` `$HOME` ``)으로 감싸거나 이스케이프(`\$`)하여 수식 렌더링 오류를 방지합니다.

---

## 5. 영문화/한글 문서 동시 동기화 원칙 (Bilingual Synchronization / Sync)

1. **1:1 완벽한 대응(Parity) 유지**: 모든 규칙과 주요 가이드 문서는 영문과 한글 쌍으로 존재합니다 (예: `rules/<이름>.md` ↔ `rules/<이름>-ko.md`, `GEMINI.md` ↔ `GEMINI-ko.md`, `README.md` ↔ `README-en.md`).
2. **동시 수정 원칙**: 어느 한쪽 문서(영문 또는 한글)의 규칙이나 내용이 추가·수정·삭제될 경우, **반드시 동일한 작업(턴/커밋) 내에서 반대편 대응 문서도 똑같이 수정하여 싱크(Sync)를 100% 일치** 시켜야 합니다. 한쪽 언어만 수정되고 방치되는 상태를 절대 허용하지 않습니다.

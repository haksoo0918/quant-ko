# 에이전트 실행 프로토콜 (Agent Execution Protocol)

이 워크스페이스에서 작업하는 모든 AI 코딩 어시스턴트와 자율 에이전트는 본 프로토콜을 반드시 준수해야 합니다.

## 1. 핵심 원칙

1. **행동 전 심층 분석**: 새로운 기능 구현, 사양 변경, 버그 수정을 시작하기 전에 요청 내용, 기존 코드베이스, 아키텍처 맥락을 철저히 분석합니다.
2. **단일 진실 공급원(SSOT)으로서의 PRD**: 기능 추가, 요구사항 변경, 데이터 스키마 수정 등 제품 동작에 영향을 주는 모든 작업은 코드 변경 전에 반드시 `./PRD.md`를 먼저 업데이트합니다.
3. **사용자의 명시적 승인 필수**: `./PRD.md`를 업데이트한 후에는 반드시 작업을 일시 멈추고 사용자에게 확인을 요청합니다. 사용자의 승인 없이 소스 코드를 임의로 수정하지 마십시오.
4. **방어적 구현 및 검증**: 코드 작성 후 테스트, 빌드, 린트 검사를 통해 변경 사항을 검증합니다. 사용자의 확인 없이 파괴적인 터미널 명령어를 실행하지 마십시오.
5. **명확한 리뷰와 릴리즈**: 변경된 파일 목록과 요약을 투명하게 공유하고, 모든 커밋은 Conventional Commits 표준을 준수합니다.

---

## 2. 5단계 실행 워크플로우
 
```
[1단계: 분석] ──> [2단계: PRD 반영] ──> [3단계: 사용자 승인] ──> [4단계: 구현 및 검증] ──> [5단계: 리뷰 및 커밋]
```

### 1단계: 분석 (Analyze)
- 요청 분류(`신규 기능`, `버그 수정`, `리팩토링`, `사양 변경`, `단순 작업`) 및 영향받는 파일·API·의존성 식별.
- **방향 제안**: 요구사항을 만족하는 2\~3가지 아키텍처/구현 방향을 심층 고민 후 사용자에게 제안 (`ask_question` 활용).
- **공식 문서 검증 & 질문**: 낯선 API는 추측하지 말고 문서/MCP를 확인하며, 모호한 요구사항은 즉시 사용자에게 질문하여 확정.

### 2단계: PRD 반영 (Update PRD)
- 선택된 방향에 따라 `./PRD.md` 업데이트 (배경, 상세 요구사항, 우선순위, 데이터/API 스펙, 검증 체크리스트).
- **예외**: 단순 스타일 수정, 경미한 버그 수정, 오탈자 정리는 PRD 생략 가능.
- *(릴리즈 이력은 PRD가 아닌 `CHANGELOG.md`에서 전담 관리)*

### 3단계: 사용자 승인 대기 (Get User Approval)
- 갱신된 PRD 요약을 사용자에게 공유하고 **명시적 승인 전까지 코드 수정 절대 금지**.

### 4단계: 구현 및 검증 (Implement & Verify)
- **멀티 에이전트 파이프라인 (`rules/multi-agent-ko.md`)**:
  - 총괄 PM 직접 구현 금지 ➔ 전문 서브에이전트(`invoke_subagent`)로 위임.
  - **화면 작업**: `frontend-agent`(`ui-ux-pro-max`, `seo`) + `ui-auditor` ➔ 스크린샷 아티팩트 출력 후 **사용자 화면 승인 전까지 대기 (Stop)**.
  - **무화면/백엔드**: 화면 승인 후 `backend-agent`(`tdd`) + `tester` 호출 ➔ TDD 올그린 검증. 누적 3회차 커밋 시 `code-reviewer` 출격.
- **TDD 사이클**: Red(실패 테스트) ➔ Green(최소 통과) ➔ Refactor(구조 개선).
- **한글 주석 & 동기화**: 주요 함수/상수 한글 주석 필수, 규칙 문서 수정 시 영문/한글 쌍 동시 수정.

### 5단계: 최종 리뷰 및 커밋 (Review & Commit)
- **단일 작업 실행 & 즉시 정지**: 사용자 확인 후 `dev` 브랜치에 한글 Conventional Commit을 실행하고 **즉시 정지**.
- **단계별 개별 승인**: 커밋 승인으로 머지나 푸시를 연쇄 실행하지 않음. 머지와 푸시는 각각 별도 지시 시에만 단계별 진행.
- `main` 머지 시 `CHANGELOG.md` 릴리즈 노트를 한글로 작성.

---

## 3. 빠른 작업 예외 규정
- 단순 스타일 변경, 경미한 버그 수정, 오탈자 정리, 읽기 전용 진단/검색은 PRD 업데이트를 생략하고 즉시 수행 가능.

---

## 4. 대용량 배치 및 장기 작업 규율 (안티 행잉 프로토콜)

1. **전체 실행 전 벤치마크 필수**: 대규모 수집, 장기 백테스트, 무거운 ETL 작업을 실행하기 전, 반드시 소규모 샘플(5\~10건)을 먼저 실행하여 건당 처리 시간과 전체 예상 소요 시간(ETA)을 산출하고 사용자에게 보고합니다.
2. **명시적 체크포인트와 타임아웃**: 백그라운드 작업을 방치하지 않습니다. 주기적인 진행 점검 타이머와 타임아웃 기준을 반드시 설정합니다.
3. **병목 감지 및 즉시 중단(Fast-Halt)**: 처리 속도가 비정상적이거나 과도한 시간이 소요될 것으로 판단되면 마냥 기다리지 않고 즉시 작업을 중단하며, 원인 분석과 대안(일괄 배치 API, 병렬 처리 등)을 보고합니다.
